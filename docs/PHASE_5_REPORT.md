## 1. What was delivered

### 1.1 gens-assets — registry core + glTF import (P5-1, P5-2; ADR-0020)
The content layer stands on one primitive: **asset identity is a pure function of (canonical key, content bytes)**. `AssetId` = FNV-1a 64 of the key (the same hash the evidence ledger uses, published-vector tested); `AssetRegistry` is an ordered `BTreeMap` with path lookup, version bumps **only when the content hash changes**, and loud errors for kind changes, id collisions, empty content and malformed keys — importing the same bytes always yields the same ids, hashes and engine objects. glTF 2.0 import produces engine-owned objects: node trees as TRS, triangle-list `MeshData` (JOINTS_0/WEIGHTS_0 parsed now so the future skinned GPU path needs no re-import), skins as gens-animation `Skeleton`s **plus inverse-bind matrices and the joint-node mapping** (the Skeleton type deliberately stores neither), and animations as `Clip`s bound to the skin they drive (LINEAR/STEP samplers, one skin per clip). The accepted subset is explicit (`UnsupportedGlTF`): CUBICSPLINE samplers, morph targets, matrix-authored nodes, morph-weight channels, multi-primitive meshes — all fail loudly; a silent partial import would be a fake implementation. The committed fixture `walker.gltf` (2-joint skin, skinned quad, 3-channel walk animation, self-contained data-URI buffer) is generated by the committed `scripts/gen_gltf_fixture.py` and verified accessor-by-accessor.

### 1.2 gens-scripting — sandboxed Rhai + entity API (P5-3, P5-4; ADR-0019)
`ScriptEngine` wraps `Engine::new_raw()`: **no packages at all** (no `print`, no filesystem, no network, no module resolver — `import` statements parse but can never resolve) plus hard limits (100 k operations, 32 call levels, 32 expression depth, 1024 map/array, 8 KiB strings) that turn runaway or hostile scripts into clean errors — CI never trusts content. The host registers the ONLY non-pure surface: a closed math vocabulary (`sqrt/floor/ceil/abs/min/max/to_int/to_float` — raw rhai has no cast operator and ships none of these), and the per-tick entity API (`now/dt`, `pos_x/y/z`/`set_pos`, kind-checked `var_num/set_var_num/var_flag/set_var_flag/var_text/set_var_text`, data-only `anim_set_param/anim_play`) operating on a value-snapshot `ScriptFrame` published through an `Arc<Mutex>` slot (rhai's `sync` feature requires `Send + Sync` natives; use is strictly sequential so the mutex never contends and determinism never depends on it). `ScriptVars` — the script-visible state — is a `BTreeMap<String, ScriptValue>` (Number/Flag/Text) with kind-checked writes and stable serde round-trips. `run_scripts` snapshots scripted entities in **entity-index order** (the ADR-0019 rule) and applies writes only on success: a failing tick leaves the entity untouched.

### 1.3 gens-runtime::save — versioned, hash-verified world persistence (P5-5; ADR-0021)
A save file is a self-contained versioned document: `GENSSAVE1` magic line, JSON body, `GENSHASH` FNV-1a trailer — verified on load (magic, hash, version), written atomically (temp file + rename, so a crash keeps the previous save). The document uses **mirror types** (`SavedTransform` as plain arrays, `SavedScript {script, entry, vars, requests}`), decoupling the on-disk format from live ECS/glam internals. `capture_world` iterates read-only and sorts by entity index — the canonical order making saves byte-deterministic; `apply_save` spawns into a FRESH world and `WorldTransform` is always re-derived, never saved. Scope stated honestly (ADR-0021): the engine-standard component vocabulary only (name/active/tag/transform/script); game state that must survive a save/load travels through `ScriptComponent::vars`; a reflection/registry layer for arbitrary components is future work.

### 1.4 Integration proof — `asset_script_hello` (P5-6)
A patrol agent whose **entire decision layer is content**: the committed `walker.gltf` supplies skeleton + walk clip + skinned mesh; the embedded `patrol.rhai` drives waypoints, movement, walk-phase accumulation and dwell through the sandboxed entity API; `run_scripts` ticks in entity order; the host samples the imported clip at the script-driven phase and writes FK offsets into `Transform`; propagation computes world transforms. **Run A** goes straight through 1200 steps; **Run B** saves at step 600, rebuilds a fresh stage, loads the save, re-derives the animation pose from the restored vars, and continues — all 60 evidence samples (positions, script vars, pose hashes) **bit-identical** between the runs. Behavioral gates, measured: x-excursion 7.997 of the 8-unit map, waypoint cycle through index 3 (the wrap), both moving/idle states observed, walk phase wrapped.

### 1.5 CI — save/replay smoke on every OS + 10-gate verify (P5-7)
`asset_script_hello` runs on **all three OS** every push (CPU-only); `smoke_asset_script.json` joins the artifacts; `verify.sh` renumbered to 10 gates mirroring CI. Run #66 produced the save/load replay evidence at **30064 bytes on Windows, Linux and macOS — byte-identical across the three** (recorded as evidence under R-013, not claimed as a guarantee).

## 4. Issues found and fixed during the phase (honest log)

1. **Double-push cancelled a CI run (#58 → #59)** — pushing the polling helper minutes after the P5-0 commit cancelled the in-flight run (same-branch supersession). Process rule adopted: one push per sub-item; the helper's own run (#60) covered both commits and went green. Recorded here because the ledger must show why #58/#59 have no green runs.
2. **rhai's default features carry a determinism hazard** — `ahash/runtime-rng` seeds hashmaps from OS randomness at runtime; rhai's script-visible maps are `BTreeMap`s, but the pin (`default-features = false, features = ["std", "sync"]`) removes the random seeding entirely, verified via `cargo tree -e features` (ahash = compile-time-rng only).
3. **rhai has NO cast operator** — `as` is module-alias syntax only; `to_int`/`to_float` live in packages the sandbox does not load. The host now registers both explicitly (part of the closed math vocabulary); the example's first compile attempt caught it.
4. **`go` is a rhai reserved keyword** — a test script function renamed (`drive`); caught by my own compile test.
5. **gltf 1.4 API drift vs older versions** — `ReadNormals` is `Iter<[f32;3]>` (no enum), indices/joints/weights/texcoords are enum-OF-iterators, `morph_targets()` (not `targets()`), the reader closure must be `Fn + Clone`, and `Target::node().index()` (not `Target::index()`). All absorbed by reading vendored source before coding; clippy additionally demanded `flatten()` over `flat_map(identity)`.
6. **gltf-rs parse-validation precedes the importer's own checks** — a POSITION-less primitive is rejected at parse time (spec enforcement), so the missing-data unit test asserts that layer honestly instead of forcing a synthetic accessor; the importer's `MissingGlTFData` path stays as defense-in-depth.
7. **STEP sampling semantics** — the earlier key holds across `[key, next)`: the second key of a 2-key track is visible only at `t = 1.0`. The import test's first expectation was mathematically wrong and was corrected (the fixture's step rotation now asserted at 0.25/0.75 = identity and 1.0 = 90°).
8. **bevy 0.16+ resources are entities** — the first save/load continuation run "reset" the agent: `build_world(false) + apply_save` had DUPLICATED it (initial spawn + loaded spawn), and `iter_entities().next()` picked the `ScriptHost` **resource entity** (no `Transform` → panic). Fixed by finding the agent by `Name`; the save format itself was unaffected (resource entities carry none of the saveable components and are correctly skipped).
9. **The animation pose is derived state** — after loading, the pose must be re-sampled from the restored vars, or the swap-step evidence hash diverges (positions/vars were already identical). This is exactly the documented save contract (derived state is never saved), and the example now enforces it with `sample_animation` after load.
10. **Behavioral gate miscalibrated twice** — x-span measured first-vs-last (the patrol returns to its start) was 0.014; corrected to max−min over the full excursion (7.997); the waypoint-cycle gate needed the run extended to 1200 steps (10 s only reached wp 2).
11. **Clippy 1.99 pedantry absorbed** — `is_multiple_of` idiom, `flat_map` identity, `let_then_return`, unused-mut on the exclusive-system host borrow; all fixed, `-D warnings` parity restored before every push.

## 6. Decisions & risks delta

- **ADR-0019** scripting (Rhai behind `new_raw`, closed math + entity API, entity-index execution order, no clocks/no RNG/runtime-rng), **ADR-0020** assets (identity = FNV(key)+content, glTF subset with loud rejection, fixture generated by a committed script), **ADR-0021** save (mirror-type versioned document, canonical entity order, atomic + hash-verified; engine-vocabulary scope stated with the reflection layer as future work).
- **RISKS:** R-013 narrowed again (the replay pin now spans input → physics → AI → animation → UI → **scripting → assets → save/load continuation**; run #66's 30064 B × 3 OS recorded as evidence, not guarantee); **R-022** new (rhai 0.x/1.x churn — pinned, raw-engine surface is small and vendored-verified); **R-023** new (save scope: resource entities occupy slots and are excluded; game-defined components need the future reflection layer); **R-024** new (script f64 ↔ engine f32 boundary conversions — conversion points are explicit and pinned by replay tests).

## 7. What Phase 6 can build on

A deterministic content pipeline (registry + glTF import) that the example proves end-to-end, a sandboxed scripting surface whose state is trivially serializable, and a save format whose continuation property is pinned by CI on every push across three operating systems. Networking + data assets (Phase 6) can define data-driven content formats on the same registry, move save state over the wire with the same hash discipline, and rely on the scripting API as the stable seam between engine and gameplay logic.
